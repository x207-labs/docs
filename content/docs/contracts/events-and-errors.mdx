## Event format

Each event is a NEP-297 log line:

```text
EVENT_JSON:{"standard":"x207","version":"0.0.18","event":"<name>","data":[{...}]}
```

`version` is the contract interface version. `data` is a list; one log can carry several items (up to 50, `MAX_EVENT_ITEMS`). A log stays under 16,384 bytes, so large results are emitted as a hash plus counts, or in chunks (`limits_updated` has `chunk` and `chunks`). The backend indexer reads these logs to build its read model. The field lists below are from `contracts/abi.json`.

## Enumerations used in events

- Member `status`: `pending`, `active`, `suspended`, `exited`.
- Position status: `due`, `paid`, `defaulted`, `claimable`, `claimed`.
- `destination`: `near`, `intents`.
- Deal `verdict`: `accused_guilty`, `complaint_false`, `no_fault`.
- Grant revoke `reason`: `grantor`, `grantee`, `operator`, `expired`, `defaulted`.
- `escrow_failed` `step`: `complete`, `cancel`.

## Errors

A failed call panics with a message that starts with a stable code, in the form `ERR_CODE: detail`. Match on the code, not on the detail. Codes below are those used in the contract source.

### Access and state

`ERR_NOT_OWNER`, `ERR_NOT_MEMBER`, `ERR_NOT_ADMITTED`, `ERR_NOT_PENDING`, `ERR_ALREADY_MEMBER`, `ERR_ALREADY_ADMITTED`, `ERR_ADMISSION_NOT_DAO`, `ERR_MEMBER_EXITED`, `ERR_EXITING`, `ERR_EXIT_NOT_READY`, `ERR_HAS_DUE`, `ERR_MAX_MEMBERS`, `ERR_PENDING_TOO_YOUNG`, `ERR_WRONG_STATUS`, `ERR_WRONG_PHASE`, `ERR_NO_STATE`, `ERR_NOT_IMPLEMENTED`, `ERR_BAD_TRANSITION`, `ERR_FROZEN`, `ERR_NOT_FROZEN`, `ERR_ALREADY_FROZEN`, `ERR_FREEZE_PENDING`, `ERR_FREEZE_NOT_PENDING`, `ERR_FREEZE_TIMELOCK`, `ERR_NO_UPGRADE`, `ERR_TIMELOCK_ACTIVE`, `ERR_CODE_HASH_MISMATCH`.

### Input and signatures

| Code | Meaning |
| --- | --- |
| `ERR_BAD_MSG` | `msg` of a token transfer is not one of the accepted shapes |
| `ERR_WRONG_TOKEN` | token is not the circle's single token |
| `ERR_BAD_PUBKEY` | `pubkey_voucher` must be an ed25519 key |
| `ERR_BAD_SIGNATURE` | ed25519 verification failed |
| `ERR_BAD_TERMS_HASH` | `terms_hash` must be 64 lowercase hex characters |
| `ERR_BAD_HASH`, `ERR_HASH_JSON`, `ERR_DUPLICATE_HASH` | malformed or repeated hash input |
| `ERR_WRONG_CIRCLE`, `ERR_WRONG_CIRCLE_ID`, `ERR_BAD_CIRCLE_ID` | circle id does not match |
| `ERR_BAD_UNIT`, `ERR_RESOURCE_NOT_ASCII` | voucher `unit` or `resource` invalid |
| `ERR_PARAM_OUT_OF_RANGE` | a param is outside its allowed range |
| `ERR_ZERO_AMOUNT` | amount must be above zero |
| `ERR_INSUFFICIENT_STORAGE_DEPOSIT` | `join` attached less than 0.35 NEAR |
| `ERR_STAKE_OVERFLOW`, `ERR_LIMIT_EXCEEDS_STAKE` | stake or limit arithmetic out of bounds |
| `ERR_GAS_TOO_LOW` | not enough gas attached for the follow-up calls |

### Vouchers and epochs

`ERR_SELF_PAYMENT`, `ERR_EPOCH_MISMATCH`, `ERR_PAST_CUTOFF`, `ERR_BEFORE_CUTOFF`, `ERR_PAYER_NOT_ACTIVE`, `ERR_PAYEE_NOT_ACTIVE`, `ERR_SEQ_NOT_INCREASING`, `ERR_SEQ_GAP`, `ERR_CUMULATIVE_DECREASED`, `ERR_INSUFFICIENT_CREDIT`, `ERR_UNKNOWN_EPOCH`, `ERR_NOT_FINALIZED`, `ERR_PRUNE_TOO_EARLY`.

### Clearing

| Code | Meaning |
| --- | --- |
| `ERR_PROPOSAL_WINDOW_CLOSED`, `ERR_PROPOSAL_WINDOW_OPEN` | wrong time for `submit_clearing` or `commit_epoch` |
| `ERR_PROPOSAL_NOT_BETTER` | the stored proposal is at least as good |
| `ERR_EMPTY_PROPOSAL` | the proposal has no edges |
| `ERR_ZERO_CLEARED` | an edge clears 0 |
| `ERR_TOO_MANY_EDGES` | more than `MAX_EDGES_PER_TX` (300) edges |
| `ERR_DUPLICATE_EDGE`, `ERR_EDGE_NOT_IN_SNAPSHOT` | repeated edge, or no obligation behind it |
| `ERR_CLEARED_EXCEEDS_OBLIGATION` | an edge clears more than the pair owes |
| `ERR_UNBALANCED_MEMBER` | a member's cleared inflow differs from its outflow |
| `ERR_PAYMENT_WINDOW_OPEN`, `ERR_PAYMENT_WINDOW_CLOSED` | wrong time for `finalize_epoch` or a residual payment |
| `ERR_NOT_DUE` | the account's position is not `due` |
| `ERR_UNDERPAYMENT` | the amount sent is below what is due |

### Claims and withdrawals
